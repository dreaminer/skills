# Blind Spot Pass

구현·설계·계획을 시작하기 전에 작업의 빈칸을 드러내고 다음 행동을 결정한다. 더 많은
아이디어를 내는 브레인스토밍이나 요구사항을 대신 확정하는 절차가 아니다.

## 증거 먼저 수집하기

1. 사용자의 요청에서 목표, 범위, 명시 제약, 이미 결정된 내용을 추출한다.
2. 작업과 직접 관계 있는 코드, 문서, 테스트, 설정, 인터페이스 계약만 읽는다.
3. 각 판단을 다음 중 하나로 구분한다.
   - **증거**: 요청 또는 확인한 작업물에 직접 있다.
   - **추론**: 증거가 시사하지만 확인되지 않았다.
   - **미확정**: 결정을 내릴 근거가 없다.

작업물에 근거한 항목에는 파일 경로나 해당 요청의 짧은 근거를 붙인다. 증거가 없으면
그럴듯한 정책이나 기술 요건을 사실처럼 추가하지 않는다.

## 관련 축만 스캔하기

아래 축 중 작업에 관계 있는 것만 검사한다. 체크리스트를 모두 나열하지 않는다.

- 성공 결과, 범위, v1 경계
- 용어의 의미, 행위자, 권한과 책임
- 사용자 흐름, 역방향·예외 흐름, 관찰 가능한 완료 조건
- 데이터, 상태 전이, 생명주기, 기존 데이터와의 호환성
- 외부 API·라이브러리·인프라·팀 작업에 대한 의존성 및 계약
- 기존 코드·문서·테스트와의 충돌
- 보안·개인정보·권한, 실패 처리, 롤아웃·되돌림, 관측성
- 테스트 범위와 실제로 검증할 수 없는 위험

각 축을 `적용`, `근거상 제외`, `미검토` 중 하나로 처분한다. `근거상 제외`와 `미검토`에는
한 줄의 이유를 남긴다.

## 항목을 처분하고 우선순위화하기

발견한 항목마다 다음 처분 중 하나를 고른다.

- **결정 필요**: 답 없이 시작하면 잘못된 결과 또는 비싼 재작업이 생긴다.
- **검증 필요**: 작은 조사·프로토타입·테스트로 사실을 확인할 수 있다.
- **명시 가정**: 보수적이고 되돌릴 수 있는 기본안을 써도 된다. 가정과 검증 시점을 남긴다.
- **범위 밖**: 이번 작업의 결과에 영향을 주지 않는다. 이유를 한 줄로 남긴다.

영향, 되돌리기 어려움, 불확실성을 함께 보아 정렬한다. 숫자로 점수를 꾸며내지 않는다.
상위 항목만 최대 다섯 개 제시하고, 근거가 약한 위험은 `미확정`으로 남긴다.

## 진행 제어

- pass만 요청받았으면 구현·문서 수정·외부 실행을 하지 않는다.
- 사용자가 pass와 구현을 함께 요청했으면 먼저 결과를 짧게 제시한다. `결정 필요`가 있으면
  가장 영향이 큰 질문 하나를 묻고 답을 기다린다.
- 사용자가 자율 진행을 명시했거나 즉시 진행을 선택했으면, 막히지 않는 항목에는 가장 보수적이고
  되돌릴 수 있는 가정을 적용한다. 가정, 이유, 후속 검증을 구현 노트나 최종 보고에 남긴다.
- 실제 충돌은 두 근거를 함께 보여 주고 해결 결정을 요청한다. 단순히 증거가 없는 상태를 충돌로
  부르지 않는다.

## 출력 형식

다음 형식으로 간결하게 보고한다.

```markdown
## Blind-spot pass

작업 이해: <목표와 현재 범위 한두 문장>
확인한 근거: <파일·문서·요청>
점검 범위: 적용 <...> | 근거상 제외 <이유> | 미검토 <이유>

| 우선순위 | 빈칸 또는 위험 | 근거와 영향 | 권장 처분 |
| --- | --- | --- | --- |
| 높음 | ... | ... | 결정 필요 — <정확한 질문> |
| 중간 | ... | ... | 검증 필요 — <검증 방법> |
| 낮음 | ... | ... | 명시 가정 — <기본안과 확인 시점> |

다음 행동: <가장 먼저 답하거나 검증할 한 가지>
```

항목이 없으면 `현재 확인한 범위에서는 구현을 막는 빈칸을 찾지 못했다`고 말하고, 검사하지 못한
축이나 증거의 한계를 명시한다. 사용자가 질문 목록을 요청하지 않은 한, 다음 행동에는 가장 중요한
질문 하나만 둔다.

## 금지 사항

- 일반론적 edge case 목록으로 결과를 부풀리지 않는다.
- 모델의 배경지식만으로 제품 정책, 권한, 도메인 의미를 확정하지 않는다.
- 해결책이나 구현 계획을 요구사항 자체와 혼동하지 않는다.
- 불확실성을 모두 차단 사유로 만들지 않는다. 되돌릴 수 있는 항목은 가정과 검증으로 진행시킨다.
- 이미 명시되었거나 증거로 확인된 결정을 다시 질문하지 않는다.
