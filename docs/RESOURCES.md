# Characterization Testing Resources

## Knowledge

- [Interview: Michael Feathers Looks Back at _Working Effectively with Legacy Code_](https://www.infoq.com/podcasts/working-effectively-legacy-code/)
  저자가 characterization test를 현재 동작의 실행 가능한 문서로 설명한다. 기존 코드를 변경하기 전에 무엇을 테스트할지 판단할 때 사용한다.
- [Book: _Working Effectively with Legacy Code_ — Michael Feathers](https://www.pearson.com/en-us/subject-catalog/p/Feathers-Working-Effectively-with-Legacy-Code/P200000008984?view=educator)
  characterization testing의 원전이다. 테스트가 없는 기존 코드를 안전하게 변경하는 구체적인 기법을 더 깊게 볼 때 사용한다.
- [Cucumber: Behaviour-Driven Development](https://cucumber.io/docs/bdd/)
  합의한 새 행동의 구체적인 예를 실행 가능한 명세로 만들고, 실패하는 테스트에서 구현을 시작하는 흐름을 설명한다. acceptance test의 기준과 작성 순서를 볼 때 사용한다.
- [Cucumber: Writing Better Gherkin](https://cucumber.io/docs/bdd/better-gherkin/)
  테스트를 구현 절차가 아니라 의도한 행동으로 기술하는 원칙을 설명한다. Essential 언어에서 acceptance test를 만들 때 사용한다.
- [Google Testing Blog: SMURF — Beyond the Test Pyramid](https://testing.googleblog.com/2024/)
  대규모 test suite를 하나의 테스트 명칭이 아니라 속도·유지비·신뢰성 등의 trade-off로 조합하는 관점을 제공한다. 조직 규모의 테스트 포트폴리오를 볼 때 사용한다.
- [AWS Prescriptive Guidance: Functional Equivalence Testing](https://docs.aws.amazon.com/prescriptive-guidance/latest/replatform-mainframe-apps-shared-db2/test.html)
  레거시 현대화에서 동일한 입력을 원본과 대상 시스템에 재생하고 출력을 비교하는 대규모 동등성 검증 사례다. characterization 방식이 프로젝트성으로 쓰이는 사례를 볼 때 사용한다.
