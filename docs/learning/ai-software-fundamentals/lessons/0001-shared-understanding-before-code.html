코드보다 먼저 공유할 것

첫 번째 실패는 모델이 약해서가 아니라, 사용자의 머릿속 설계가 입력에 없어서 생긴다.

질문의 목적은 정보를 많이 모으는 것이 아니라, 서로 다른 구현으로 갈라지는 결정을 드러내는 것이다.

영상의 주장

영상 2:36부터는 AI가 의도와 다른 것을 만드는 원인을 ‘공유되지 않은 디자인 콘셉트’로 설명한다. 처방인 Grill Me는 AI가 같은 이해에 도달할 때까지 사용자를 집요하게 인터뷰하게 한다.

2026년에도 맞는가?

맞다. 다만 “40~100개 질문”은 성공 조건이 아니다. GPT-5.6 같은 최신 모델은 의도 추적과 장기 코딩이 크게 나아졌다. 그럼에도 OpenAI가 전 코드 생성 프로젝트에서 발견한 초기 병목은 모델 능력보다 불충분하게 명세된 환경이었다. METR의 최신 평가도 모델이 특히 잘하는 작업은 성공 기준이 명확하고 자기완결적이라고 명시한다.

모델은 말하지 않은 제품 결정을 읽는 것이 아니라 그럴듯한 기본값으로 메운다. 최신 모델일수록 그 기본값을 더 능숙하고 멀리 실행하므로, 틀린 방향의 비용도 커질 수 있다.

질문해야 할 것과 기본값으로 둘 것

반드시 질문대개 기본값 선언
사용자에게 보이는 행동이 달라지는 결정프로젝트 관례로 되돌릴 수 있는 파일 배치
데이터 손실·권한·비용·호환성에 관한 결정자동 포매터가 정하는 표현 방식
두 답이 서로 다른 모듈 경계를 만드는 결정기존 명명 규칙으로 쉽게 고칠 수 있는 이름

2026년형 Grill Me

  1. 결과: 누가 무엇을 할 수 있게 되는가?
  2. 관찰: 성공과 실패를 무엇으로 판정하는가?
  3. 경계: 바꿀 것과 바꾸지 않을 것은 무엇인가?
  4. 위험: 되돌리기 어렵거나 사람의 정책 판단이 필요한 것은 무엇인가?
  5. 중단: 답에 따라 행동·경계·데이터·위험이 달라지는 미결정 사항이 없으면 구현으로 넘어간다.
계획 전에 질문해라.
단, 답이 사용자 행동·모듈 경계·데이터·위험을 바꾸는 질문만 해라.
되돌릴 수 있는 세부사항은 프로젝트 관례를 기본값으로 선언해라.
미결정 사항과 합의된 acceptance example을 요약한 뒤 멈춰라.

짧은 연습

요청이 “오래된 후보를 자동 정리해줘”뿐이라면, 구현 전에 가장 먼저 물을 질문은?

  1. 새 파일은 어느 폴더에 둘까요?
  2. 오래됨은 무엇이고 결과는 삭제인가요?
  3. 새 함수는 어떤 이름으로 만들까요?
정답과 피드백

B. ‘오래됨’의 기준과 ‘정리’가 삭제인지 보관인지에 따라 사용자 행동과 데이터 손실 위험이 달라진다. A와 C는 저장소 관례를 따른 뒤 쉽게 되돌릴 수 있다.

다음 레슨으로 가기 전에 자신의 실제 요청 하나를 결과·관찰·경계·위험 네 줄로 다시 써 보라. 막히는 줄이 바로 AI가 추측하게 될 부분이다.

이제 그 합의 중 반복되는 애매한 말을 고정하는 두 번째 레슨: 큰 용어집 대신 작은 계약으로 이어진다. 추가 질문은 에이전트에게 물어보라. 전체 위치는 2026 유효성 지도에서 확인할 수 있다.
