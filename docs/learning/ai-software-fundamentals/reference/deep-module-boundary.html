깊은 모듈 경계 점검표

깊이는 파일 줄 수가 아니라, 작은 인터페이스 뒤에 안전하게 감춘 결정의 양이다.

점검 질문“예”라면
호출자가 내부 조건의 순서·임계값을 알아야 하는가?경계가 새고 있다. 도메인 질문 하나로 감춘다.
정책 변경 때 호출자 여러 곳을 수정해야 하는가?변경 축을 모듈 안에 모은다.
외부에는 결과만 필요하고 중간 상태는 필요 없는가?중간 상태를 비공개로 둔다.
인터페이스 계약만으로 모듈을 테스트할 수 있는가?좋은 경계의 신호다.

앞선 정책에 적용

나쁜 경계: hasLoggedIn(), lastLoginAge(), isTestAccount(), isSuspended()
좋은 경계: notificationEligibility.shouldSend(user, now)

계약: 한 번 이상 로그인했고 마지막 로그인이 now보다 30일 초과 과거이면 false.
정확히 30일 전이면 true. 내부 제외 규칙은 이 경계 안에 둔다.

좋은 경계는 호출자에게 “누구에게 보낼까?”만 답하게 한다. 날짜 계산, 제외 규칙, 데이터 조회 방식은 모듈 내부에서 바꿀 수 있다.
