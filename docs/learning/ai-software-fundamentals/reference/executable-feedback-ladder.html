실행 가능한 피드백 사다리

리스크가 발생하는 곳과 같은 층위에서, 가장 싼 자동 검증을 고른다.

깨질 수 있는 것우선 피드백관찰할 결과
정책·계산·경계값단위 테스트입력별 결정값
데이터·외부 서비스 연결통합 테스트실제 연결 뒤 결과
사용자 흐름·화면브라우저/종단간 검증사용자가 보는 행동
성능·운영 상태로그·메트릭·추적 검증시간, 오류, 관측값

선택 절차

  1. “이 변경이 틀렸다면 사용자는 무엇을 보거나 잃는가?”를 한 문장으로 쓴다.
  2. 그 결과를 직접 반증하는 가장 좁은 자동 검증을 고른다.
  3. 에이전트가 구현 전 실패하게 만들고, 구현 뒤 같은 명령으로 통과를 보인다.
  4. 더 넓은 층위의 위험이 남을 때만 통합·브라우저·관측 검증을 추가한다.

앞선 연습에 적용

위험: 30일 초과 사용자가 알림을 받거나, 정확히 30일 사용자가 누락된다.
우선 검증: 비활성 판정 단위 테스트
경계 사례: 30일 정확히 → false, 30일 + 1초 → true
연결 검증: true인 사용자가 발송 작업에서 제외되는 통합 테스트
