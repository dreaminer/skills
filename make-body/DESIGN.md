# Make Body — Design

`SKILL.md` is the executable contract. This file records why that contract has its current shape.

## North Star

Recover human-confirmed business meaning from an existing implementation while keeping each
truth-maker in one place.

```text
System behavior   -> project-owned executable tests
Test qualification -> TEST_FLOWS_RESULT.md, regenerated by test-flows
System explanation -> QUICK_UNDERSTANDING.md, regenerated from effective tests
Essential meaning -> ESSENTIAL_DOMAIN.md + ESSENTIAL_USECASE.md, ratified by a human
```

The qualification result is a receipt, not another behavior authority. Make Body owns only the
Essential line.

## R6 decision — System leaves Make Body

Earlier revisions created canonical System prose, characterization lock registries, and later an
`ACCEPTANCE.md` linked to tests. Each form repeated behavior that executable tests already expressed
and created two authorities that could drift.

R6 removes the duplication. Make Body consumes qualified flow evidence but does not create, modify,
identify, link, or explain System tests. `test-flows` and `explain-flows` remain independent skills;
Make Body neither invokes them automatically nor changes their contracts.

The Essential body returns to two documents because Domain and UseCase have different shapes and
both are human meaning rather than a second System description.

## Why no Acceptance layer

In a code-recovery workflow an Acceptance document sat between human meaning and executable tests:

```text
Essential hypothesis -> Acceptance prose -> linked test
```

The middle layer repeated Given/When/Then while adding a marker/hash lifecycle. Deleting it removes
that lifecycle and leaves the two actual truth-makers: human-ratified Essential and executable
System behavior.

This decision applies only to Make Body. It does not constrain `seed-body` or `seed-system`, whose
greenfield responsibilities and artifacts are independent.

## Input seam

Make Body requires regression-effective flow evidence. It does not recreate the evidence workflow
because doing so would make it a shallow wrapper over `test-flows`. Missing evidence is an explicit
terminal outcome, `NEEDS_FLOW_EVIDENCE`.

`test-flows` communicates completion through `TEST_FLOWS_RESULT.md`. A ready result names the
project-owned evidence tests and maintained test commands and asserts that Test Flows completed its
regression-fitness work. Make Body reruns those commands against the current project, then reads the
tests and production decisions. It does not demand Test Flows' internal mutation trace or repeat red
proof.

`QUICK_UNDERSTANDING.md` is an optional navigation view. Make Body reads the underlying test and
production decision before drafting a hypothesis, so a regenerated explanation cannot silently
become Essential truth.

## Semantic compression

Essential recovery is not a one-to-one translation:

- a technical test may carry no business meaning;
- multiple tests may implement one Essential UseCase;
- one observed flow may suggest several competing meanings and therefore produce a conflict;
- no candidate becomes canonical without human ratification.

The admission test is information gain: after implementation machinery is removed, the hypothesis
must say something a human recognizes as business identity, responsibility, policy, invariant, or
outcome. A vocabulary-only paraphrase is rejected.

## Minimal deterministic layer

Scripts enforce only what is mechanical:

- runtime availability;
- managed-file initialization;
- canonical document shape, references, and human-ratification evidence;
- workspace audit and counts.

Scripts do not collect code facts, infer flows, classify meaning, author candidates, link tests, or
decide whether a hypothesis is valuable. Those responsibilities either belong to the independent
flow skills or require human judgment.

## Migration

Old System, Acceptance, and lock artifacts are preserved rather than rejected or auto-converted.
Their provenance is ambiguous: they may express actuality, intent, or obsolete design. They can aid
navigation but cannot establish Essential meaning.

## Independence test

- Deleting Make Body leaves `test-flows` and `explain-flows` fully usable.
- Deleting either flow skill does not change Make Body's canonical format; it only affects whether
  qualified input evidence is available.
- Changing seed skills does not require a Make Body migration, and changing Make Body does not
  require a seed migration.

These are separate modules with separate interfaces, not forward and reverse adapters of one shared
protocol.
