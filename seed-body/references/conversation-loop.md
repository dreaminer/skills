# Seed Body 대화 루프

발산 국면에서는 사용자가 편하게 말하게 두고, 정리 부담은 에이전트가 진다. 매 턴 아래 순서를
지켜 Essential만 코퍼스에 들인다.

## 턴 처리 순서

1. **발화 근거 고정** — 새 발화의 턴 번호(`T{n}`)와 짧은 직접 인용을 먼저 잡는다. 이 단계에서는
   아직 `ESSENTIAL_FLOWS`에 쓰지 않는다.
2. **Essential admission** — 문장에 기술어가 있는지가 아니라 사용자가 요구하는 의미를 판정한다.
   - **Essential**: 행위자의 의도·책임, 관측 가능한 결과, 업무 정책, 성공을 판정하는 품질 제약.
     시간·복구·가용성 표현도 사용자가 그 자체를 성공 조건으로 요구하면 Essential이다.
   - **파킹**: 사용자가 Essential을 달성하는 **방법**으로 말한 실행·운영·기술 조각. 푸시·API·
     DB·프레임워크뿐 아니라 재시도·재접속 동작도 사용자가 성공 결과가 아닌 방법으로 말하면
     포함한다. `SYSTEM_PARKING`에 원문 그대로 보존하고 System/Implementation을 더 분류하거나
     타당성을 판정하지 않는다.
   - **혼합/애매**: Essential과 구현 수단의 분리를 문장으로 제안해 한 번 비준받는다. 예를 들어
     “푸시로 5초 안에 공지가 떠야 해”는 `공지가 5초 안에 보인다`가 성공 조건인지 먼저 확인하고,
     그렇다면 그것은 Essential로 두고 `푸시`만 파킹한다. 비준 전 조각은 `[층미분류]`로 둔다.
3. **되비춤과 기록** — admission이 끝난 Essential 조각만
   `[행위자]가 [상황/트리거]일 때 [하려는 것] → [기대 결과]` 문장으로 되비춘다. 사용자
   vocabulary를 유지하고 후보 용어를 `{term}`으로 마킹해 `SEED_BODY_ESSENTIAL_FLOWS.md`에
   `EF-nnn`으로 누적한다. 파킹 조각은 `SF-nnn`으로 기록하고 받치는 `EF-nnn`을 `Trace:`로 단다.
   받치는 Essential이 아직 없으면 파킹하지 말고 `[층미분류]`로 유지한다.
4. **v1 경계** — v1 밖으로 보이는 Essential은 “이건 v1 다음으로 미뤄둘까?”라고 확인한다.
   승인되면 `SEED_BODY_LATER.md`에, v1 코어라면 코퍼스에 둔다.
5. **승격 체크** — 이번 턴의 LATER 항목이 v1 뼈대의 빈 슬롯을 가리키면 “이건 사실 v1 코어
   아닐까?”를 한 번만 확인한다. YES면 코퍼스로 되돌리고 NO면 그대로 둔다.
6. **회전** — 종료 임박 신호가 없으면 가장 값진 빈/약한 슬롯 하나만 질문한다. 후보 슬롯에는
   흐름 빈칸, 역방향·예외, 복수 행위자의 권한 충돌, 위험한 외부 약속, PRIOR 미처분 항목이
   포함된다. v1 코어 UseCase마다 역방향·예외를 한 번은 질문하거나 명시적 `해당 없음`·유보·
   v1 밖으로 처분한다.

## 카테고리 프라이어 — 위험순 질문 재료

서비스 카테고리를 식별할 수 있을 때 `SEED_BODY_PRIOR.md`를 만든다. 한 run에서 PR 항목은
**최대 7개**다. 다음 순서로 “빠뜨리면 v1 핵심 가치·신뢰·안전이 깨질 가능성”이 큰 Essential
빈틈만 고른다.

1. 핵심 가치가 전달되는 주 흐름
2. 실패·취소·되돌림처럼 비가역 결과를 막는 흐름
3. 같은 대상을 다루는 행위자의 권한·충돌
4. 외부 사람·기관과의 약속, 신뢰·안전 위험

기능 동등성 체크리스트와 구현 관심사는 제외한다. LLM 지식과 웹 근거는 질문을 고르는 데만 쓰고
후보·Evidence로 쓰지 않는다. 카테고리 이해가 바뀌면 항목을 계속 추가하지 말고, 아직 묻지 않은
낮은 위험 항목을 교체해 전체를 7개 이하로 유지한다.

각 PR 항목은 다음 중 하나로 처분한다.

- 답 → `EF-nnn`
- 해당 없음 → 사용자 확인 턴
- 유보 → `QUESTIONS`
- v1 밖 → 사용자 승인 후 `LATER`

처분될 때까지 회전 풀에 남기되 같은 항목을 두 번 연속 묻지 않는다. 점검표를 읽어주지 말고
구체 시나리오로 질문한다.

## 질문 3갈래 처분

빈칸이나 모호함을 다음처럼 처리한다.

- **유추 가능** — 구체 제안값을 `[가정]`으로 큐잉하고 “이렇게 보면 맞아?”라고 한 번 묻는다.
- **사용자가 답할 수 있음** — 한 번에 질문 하나만 묻는다.
- **지금 결정하지 않음** — 사용자의 유보를 `SEED_BODY_QUESTIONS.md`에 기록하고 회전한다.

같은 슬롯은 연속으로 묻지 않는다. 단 하나 남은 필수 질문이면 그 사실을 짧게 밝히고 닫는다.
현재 질문과 무관한 응답을 억지로 Evidence에 연결하지 않는다. 새 Essential 아이디어라면 admission과
v1 확인을 거치고, 단순 여담이면 대화에만 남긴 뒤 원래 회전으로 돌아간다.

같은 개념에 두 용어가 나오면 `[충돌]`로 큐잉하고 사용자의 누적 사용 이력으로 수렴을 제안한다.
발산 중 Domain은 `{term}` 마킹으로만 유지한다. Domain 후보 생성과 재기술은 종료 게이트의
harvest에서 한 번 수행한다.

## 종료 임박 휴리스틱

다음 중 하나를 만족하면 [closing-gate](closing-gate.md)로 진입한다.

1. **명시 신호** — “다 말한 듯”, “다음 단계는?”, PRD·프로토타입 등 downstream 요청
2. **대화 정체** — 새 조각 없는 회전 2턴 이상 또는 응답 고갈; “v1 코어에 더 보탤 게 있어?”를
   한 번 확인한 뒤 진입
3. **자기 완결성** — 실제 용어로 “누가 어떤 흐름을 통해 어떤 가치를 얻는가”를 placeholder 없이
   쓸 수 있음; 조용히 게이트로 들어가 메타 비준을 제시하고, 사용자가 부정하면 회전으로 복귀

게이트 진입은 종료가 아니라 수렴 시작이다. CRITERIA가 미답을 발견하면 다시 한 질문씩 회전한다.

## 첫 턴

호출문에 서비스 조각이 없으면 “어떤 서비스를 만들고 싶어? 상황 떠오르는 대로 편하게 말해줘 —
정리는 내가 할게.”라고 한 줄만 초대한다. 호출문에 이미 서비스 조각이 있으면 초대를 반복하지 않고
곧바로 admission을 거쳐 문장형으로 되비춘 뒤 가장 중요한 빈 슬롯 하나를 묻는다.
